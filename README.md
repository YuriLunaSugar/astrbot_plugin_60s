# 60s 日更与热门榜单

为 AstrBot 提供每天60秒、历史上的今天定时发送，以及日更和热门榜单查询。成功消息只发送接口原始图片或文字，不添加插件标题、日期、来源或页脚；帮助和错误反馈正常保留。

## 安装

1. 打开 AstrBot 管理面板的「插件」页面，选择「安装插件」→「从链接安装」。
2. 填入仓库地址：`https://github.com/YuriLunaSugar/astrbot_plugin_60s`。
3. 安装后，在「已安装」中确认插件已启用且没有加载错误，再打开插件配置。
4. 在已接入机器人的会话中发送 `/60s 帮助` 或 `/history help`，确认命令可用。

若安装或加载失败，先查看 AstrBot 日志，检查插件声明的兼容要求、依赖安装和网络连接。安装操作说明见 [AstrBot 插件使用文档](https://docs.astrbot.app/use/plugin.html)。

下文 `/` 是示例前缀；实际使用 AstrBot 配置的命令前缀，并遵循其会话权限设置。

## 配置定时发送

初始状态下，主动发送总开关关闭，发送目标为空。每个目标、每个日更接口分别设置格式和时间。

1. 在「发送目标与日更格式」中点击「添加条目」，再选择菜单中的「发送目标」。
2. 展开条目，在「目标会话 UMO」中选择实际会话。选择后，完整 UMO 会显示在条目标题下方。
3. 分别设置每天60秒和历史上的今天的发送格式、开始时间、等待间隔、结束时间。
4. 保存配置，确认目标和时间无误后，开启「启用主动发送」。

每个 UMO 只添加一条。请从 AstrBot 会话选择器选择真实会话；开发调试时也可读取消息事件的 `event.unified_msg_origin`。UMO 不是裸群号或 API 地址。

虚构的格式示例：`example_bot:GroupMessage:demo_group_A`。必须替换为实际完整 UMO，不能直接使用示例投递。

### 全局设置

| 配置 | 用法 |
| --- | --- |
| 主动发送开关 | 关闭后停止全部定时发送，不影响手动查询 |
| `base_url` | 默认 `https://60s.viki.moe`，填写服务基址，不包含 `/v2`；可使用自己的 HTTP/HTTPS API |
| `timezone` | 默认 `Asia/Shanghai`，使用 IANA 时区名称 |
| `timeout_seconds` | 默认 20 秒，可设置 1–120 秒，用于请求、格式准备和单次发送 |

### 每个目标的设置

| 设置 | 每天60秒 | 历史上的今天 |
| --- | --- | --- |
| 默认格式 | `image` | `text` |
| 可选格式 | `image`、`text`、`json`、`markdown`、关闭 | `text`、`json`、`markdown`、关闭 |
| 默认开始时间 | `09:00` | `09:00` |
| 默认等待间隔 | 15 分钟 | 15 分钟 |
| 默认结束时间 | `11:00` | `11:00` |

时间使用 `HH:MM`，等待间隔为 1–1440 分钟。开始和结束时间不能相同；结束早于开始表示跨午夜。结束边界为该分钟的第 0 秒，包含此时刻，之后停止尝试。

选「关闭」只停止当前目标的当前接口。删除条目会移除目标；删除全部条目后不再主动发送。已有配置会保留原设置，请不要手动修改隐藏的迁移标记。

## 手动查询日更

```text
/60s
/60s text
/60s json
/60s markdown
/history
/history json
/history markdown
/60s 帮助
/history help
```

- `/60s` 默认发送图片；`/history` 默认发送文字，历史接口不支持图片。
- 每条命令只回复发起会话，不开启定时任务，也不改变定时发送记录。
- 即使主动发送关闭、未配置目标或目标接口已关闭，仍可手动查询。
- 不接受日期或其他发送目标参数。手动查询返回上游当前提供的内容，可能是旧内容，不另加日期说明。
- 每次手动查询重新请求，不使用日更结果缓存；失败不会自动循环重试。遇到限流，请按错误提示等待。

文字格式直接请求对应的 `text`、`json` 或 `markdown` 并保留原文。图片先请求 `image`，读取跳转文件名日期；无法解析时额外请求 JSON 日期，再下载图片。通常是一次 API 查询，日期回退时是两次，跳转下载另产生 HTTP 请求。

## 查询热门榜单

```text
/hot 帮助
/hot weibo
/hot weibo markdown
/hot 小红书 json
/hot 网易云榜单
/hot 网易云详情 3779629 json
/hot hn best markdown
/hot IT之家 week text
```

格式放在末尾，只能出现一次；默认 `text`，支持 `text/json/markdown`，不支持 `image`。网易云详情的榜单 ID 请先通过「网易云榜单」查询；示例 ID 按实际结果替换。

HackerNews 可选 `top/new/best`，默认 `top`；IT之家可选 `day/week/month`，默认 `day`。

也可使用 `/hot weibo 10` 这样的旧条数参数，允许 1–20，但插件不截取原文，实际条数由上游接口决定。相同榜单和格式缓存 60 秒；不同格式分别获取，频繁查询可能触发等待提示。

## 重试、日期与使用限制

- 定时任务约每 30 秒检查一次，实际发送可能稍晚。未成功时按该目标、该接口的等待间隔重试，超过结束时间停止；错过整个窗口不补发。
- 定时日报图片优先从跳转地址的完整日期文件名判断日期，无法解析时使用 JSON 的 `data.date`。只有日期同时符合配置时区的今天和计划日期才发送；旧日、未来或未知日期继续等待。
- 定时文字先用 JSON 检查计划日期及有效内容；`json` 复用原始响应，`text/markdown` 再获取相应原文。历史缺少有效事件时不发送。
- 跨午夜窗口归属于开始日。日报图片不会在次日发送昨日图片；上游已切换到次日内容时，也可能不符合原计划日期而停止该轮发送。需要次日内容时，请设置次日的开始时间。
- 文件名日期不能证明图片内容日期。JSON 判日与随后图片或文字获取不是原子操作，上游切换内容时仍可能不一致。
- 同一轮多个目标共享相同请求。成功目标当天不重复发送；平台明确返回失败才自动重试。超时、异常或中断可能意味着已投递，插件不会盲目重发，请先人工核查。
- 重启保留成功、结果不明和等待状态。请保留 AstrBot 数据目录下的 `plugin_data/astrbot_plugin_60s/deliveries.sqlite3`，不要让多个进程同时运行同一套定时任务。
- HTTP 429 会遵守 `Retry-After`，等待时间可能长于配置间隔。遇到网络或上游错误，请检查 API 连通性及日志，不要频繁重复触发。
- 图片只发图片；文字保留接口自己的标题、日期和链接，不添加插件说明、不截断或拆分。文字响应超过 1MB 会报错；平台自身的消息长度或图片限制仍然适用。

## 常见问题

**添加条目后没有新配置？** 先点击「添加条目」，再选择下拉菜单里的「发送目标」，最后展开新增条目选择 UMO。

**手动查询成功，但定时没发送？** 检查主动发送开关、目标 UMO、接口是否关闭、时区和发送窗口；确认平台适配器支持主动发送，再检查日志中的日期、限流或投递状态。

**图片取不到或发送失败？** 检查 API 基址、跳转地址的网络可达性及平台图片支持。无需配置图片域名白名单。也可将该目标日报格式改为 `text`。

**为什么消息仍有标题或来源？** 插件只转发接口原文，上游原文自带的内容不会删除。

更多接口说明见 [60s API 文档](https://docs.60s-api.viki.moe/)。请遵守上游内容的使用条款。
